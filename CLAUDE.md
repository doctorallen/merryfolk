# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Merryfolk is a browser artificial-life game (a *Creatures*-style hobbit village) in plain JavaScript: no build step, no dependencies, no modules. `README.md` describes every feature in detail, so read the relevant section before changing a system, and keep it in step when behavior changes.

## Commands

```sh
python3 -m http.server 8000                         # play at http://localhost:8000 (or just open index.html)
npm ci                                              # once per clone: puppeteer-core and typescript (dev only)
npm test                                            # everything CI runs: check, golden, sprites, pictures, gpu, smoke, minds, valley, wizard, talk, pwa
node test/season.js                                 # a season's numbers (meals, work, weddings, moods, natters, the body, harm), to compare before and after a change to the minds
sh test/check.sh                                    # syntax, every script listed in index.html, tsc
npx tsc -p .                                        # the type check alone (files marked // @ts-check)
node test/golden.js --update                        # re-record test/golden.json after an intended world-gen change
node test/pictures.js --update                      # re-record test/pictures.json after an intended change to the painting
node test/icons.js                                  # draw the app's icons again (icons/) from the game's own tree
git config core.hooksPath .githooks                 # once per clone: the pre-commit hook stamps js/version.js
```

The tests live in `test/` and run against the installed Chrome (set `CHROME` if it isn't at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`). `golden.js` hashes the generated world for three classic seeds and a valley, so any change to world generation must be intended and re-recorded; `sprites.js` hashes a few fixed villagers' sprites; `pictures.js` hashes what the same worlds paint (the ground chunk by chunk, a sample of the scenery through the seasons, the tufts, the night's light pools, the interiors) and leaves screenshots of fixed views in `test/out/`; `smoke.js` plays two days on desktop and phone, checks the numbers stay finite and nobody is stuck, round-trips the save, and loads it written with the old British names; `minds.js` checks the minds on Tyrell (folk eat and sleep, and the same seed gives the same minds, hash for hash); `season.js` (by hand) plays three seeds for three days and writes a season's numbers (`test/season-*.json`, compared in `test/minds.md`); `valley.js` checks every building in a planned valley is reachable; `wizard.js` plays as the wizard on a phone (a talk, a tale, his fireworks, a night's sleep, a journey, the save); `talk.js` lints the talk packs and fuzzes a couple of hundred conversations; `pwa.js` serves the game over http as the deploy does and checks the installed game: the worker keeps it and the talk packs, a new deploy is loaded onto, one already running isn't, and offline it still opens. There is no linter. CI (`.github/workflows/pages.yml`) runs `npm test` and deploys `main` to GitHub Pages only when it passes. Every push to `main` goes live.

Verify changes by driving the game headlessly with `puppeteer-core`: `test/lib.js` has `launch()` and `openGame(browser, { width, height, mobile })`, which open a fresh game and collect every page error, and the test scripts show the idiom. One-off scripts go in a scratch directory (`test/out/` is gitignored), and never install packages into the repo beyond `package.json`. The `qa-playtester` agent (`.claude/agents/qa-playtester.md`) has the full recipe. The essentials are:

- Wait for `typeof Game !== 'undefined' && Game.villagers.length > 0`, then call `startGame(false)`.
- `simulate(0.5)` advances half a game minute, so 2880 calls make one day.
- `save()` / `load()` round-trip the save.
- Set `Game.zoom` (steps 2/4/6/8), `Game.cam.x/y` and `Game.speed = 0` for screenshots.
- Wait for `!World.paintJob` before judging the ground, which paints in the background.
- Catch every `pageerror`.

For visual changes, look at the screenshots, and compare against a `git archive HEAD` copy for performance or regressions.

## Architecture

**Installable, never stale.** Served over the web, the game is an installable app: `manifest.webmanifest`, `icons/` (drawn from one of the valley's trees by `test/icons.js`) and `sw.js`, a few lines that import Tycho's worker (`vendor/tycho/dist/tycho-sw.js`; Tycho, the shared engine, is a git submodule at `vendor/tycho`), which goes to the network first for everything and uses its cache only offline, keeping what `index.html` names and the talk packs. Don't make it cache-first. The deploy stamps `__BUILD__` in `sw.js` with the commit and writes `version.json` with `BUILD_INFO`; `js/pwa.js` runs Tycho's installable app (`Tycho.pwa`), which looks for a new deploy when the game comes back to the foreground and every 15 minutes, and when one takes over saves the village and loads onto it. Opened from a file, none of that runs and the game plays as a page.

**Globals and load order.** Every file is a classic script sharing one global scope: `Game` (clock, villagers, player state), `World` (map, statics, homes, lots), `Village` (stores, projects), `Sound`, `FX`, `Light`. Order in `index.html` matters, with `util.js` first and `main.js` last. A new file needs a `<script>` tag there.

**Hooks and patches.** Later files add to earlier ones through two helpers in `util.js`. `addHook(name, fn)` registers a function for one of the moments in `Hooks`: `beforeHour` and `onHour` (from `onHour` in `main.js`, before and after the clock's own work), `newVillage` and `afterNewVillage` (either side of founding). `patch(obj, key, make, label)` replaces a method or function with one that wraps the original, as in `patch(Villager.prototype, 'speak', (speak) => function (...) { ...; return speak.apply(this, arguments); }, 'manner')`, and records it in `PATCHES`, which the dev drawer's Tools tab lists. A few global functions are still reassigned outright (`name = function`); before editing a function, grep for its patches and reassignments, or the change may be overridden. `fixes2.js` is a file of such patches from a playtest.

**Adding a feature file.** Create `js/<name>.js` beginning with `'use strict';` and a banner comment saying what it does; add its `<script>` tag to `index.html` in the right group, after every file it uses (`test/check.sh` fails on a file that isn't listed); add a row to the file table at the end of `README.md` and describe the feature in the relevant section; hook into the clock and founding with `addHook`, and wrap existing behavior with `patch`; keep any new persistent state in `Game` and register it with `registerField(key, default, opts)` (`save.js`) so it is saved and loaded, or add it to `Villager.serialize` and the constructor if it belongs to a villager; make anything placed in the world deterministic from the seed or an id; then run `npm test`, and re-record the golden hashes only if world generation was meant to change.

**Units.** Positions are world pixels, with `TILE` = 16 and the map `MAP_W`×`MAP_H` tiles (128×96). Tile kinds are in `T` (`world.js`). Villager logic runs in game minutes. Paths are Tycho's A* (`Tycho.path.AStar`, `PF` in `world.js`, remade by `setMapSize`): `findPath` and `nearestWalkable` ask it, the game saying what's walkable and what each step costs (`stepCost`: the ground's `TILE_COST` and a bank's climb).

**Loop.** `frame()` (`main.js`) runs `simulate(dt)` in steps of at most 0.5 game minutes, then `render()`. Each villager's update runs in its own try/catch: an error drops that villager's task, is noted on `Game.lastError` (the dev drawer shows a red `!`), and holds off the routine autosave for a game hour. Hourly and daily work (`onHour` with its hooks, `dailySociety`, `checkSeason`) fires from `simulate`.

**Input and dev settings.** The camera's keys (WASD and the arrows) are actions held on Tycho's controls (`CamKeys` in `main.js`, a `Tycho.input.Controls` with keys and axes only), fed the keys' names by the game's own key listener, which keeps the shortcuts and ignores typing in a field. The pointer is the game's own (`setupInput`): past six pixels a drag picks up the villager under it (the giant hand) or pans by its whole offset, and a pinch zooms in whole steps from its start, touches only, never while carrying; Tycho's gestures pan and pinch by steps between moves, so they'd change it. The dev drawer's settings are Tycho's dev flags (`DevFlags` in `dev.js`, under `merryfolk-dev`, never in the save), and the wizard's pack is a bag of counts (`Tycho.items.bag`, `Pack` in `play.js`).

**Saves rebuild the world from its seed.** `save()` (`save.js`) writes player and villager state to `localStorage` through Tycho's save store (`SaveStore`, a `Tycho.save.Store`: its storage never throws, and the old names in `RENAMED` are put right in the save's text as it's read, `SAVE_RENAMES`), plus the world-gen settings (`World.gen`), but not the map. Plain fields of `Game` are listed in `GAME_FIELDS` (features add theirs with `registerField`); anything that needs a transform is written by hand in `save()` and `load()`. `load()` regenerates the valley through `buildWorldSteps` (`world.js`, a generator that yields a line per stage for the setup screen). It then replays builds (`replayBuilds`) and town lots (`loadTown`), and re-furnishes homes. So anything placed at world generation must be deterministic from the seed, or from ids such as a home's id (`mulberry32(...)`, `hash2`), never `Math.random`. Anything added mid-game must be saved explicitly, or recreated by the replay path. New home plots go through `openLot` (`town.js`).

**Village life.** Villagers (`villager.js`) have drives and body chemistry, and choose actions from the catalog in `actions.js` by scored relief times learned habit weights; the dev-mode Brain tab (`` ` ``) explains each choice (Palantír's record of it, `devBrainMind`). `society.js` handles the Common Store, trades, courtship, births and homes, and `town.js` handles town planning and building projects.

**The minds are Tyrell's.** Tyrell (`vendor/tycho/dist/tyrell.js`, loaded before the game's own scripts with Tycho and the bridge, `tycho-minds.js`) runs every villager's needs and choices; `js/shell.js` is Merryfolk's shell for it (`Shell`, whose banner says what lives where) and `js/minds.js` its needs and feelings. Tyrell holds the needs (Bicameral, each villager's rates from genes, age, trade and the season, `mindRates`, and what illness and ale do to them, Athelas's courses), the habits (learned by the game's own rule, `learnFrom` in villager.js, and your pats, both given to Tyrell through `reward`; Tyrell's own learning is off, its `habits` setting 0 in `MIND_CONFIG`), the choice (every reason the old `score()` gave reaches it as a factor through the game's module, `MIND_MODULE`; urgent needs break in), genes (Delos), births, couples and parents (Cradle, Fellowship's partners), skills, work rounds (Mentat), the Common Store's stock and chains (Ceres), feelings and memories (Reverie), regard and friendships (Fellowship), what passes between them (Bree: natters, squabbles, sweet-talk, making up and table talk, below), the body (Athelas: ale, colds, the flu, toadstools, sprains) and harm (Morgul: scuffles, pranks, below), and chance (its streams, from `Game.mindSeed`). The game's old fields (needs, habits, skills, moodlets, memories, rel, love, sentiments, `Village.stores`) are views over Tyrell's state, so the rest of the game reads them as before. What stays the game's: space (Tyrell has no coordinates: the game walks folk where an action needs, and tells Tyrell it's done, stopped part way, `mf.stop`, or impossible; each villager has a private Tyrell place, `at_v<id>`), imitation, catching things and drinking (who sat beside whom), breaks, wishes, dreams and pastimes, aging and matching couples. Time walk (Esper) is off, and the minds' clock follows the game's (`Shell.advance` from `simulate`). The minds are saved as Tyrell's own state (`Game.minds`, through the bridge's `stash` and `restore`); a save from before them is made into fresh minds from each villager, carrying over what they were. Each moment is thought over once (`checksOnce`), and a choice is checked against the valley as it begins. Tyrell's numbers are all settings (`vendor/tycho/tyrell/docs/tuning.md`); Merryfolk's are `MIND_CONFIG` and `MIND_MODULES` in shell.js. Change the minds and run `node test/season.js` to see what moved.

**Natters.** With the minds on Tyrell, the natters between villagers are Bree's, Tyrell's module for interactions between people (`js/bree.js`, `Natter`; its docs are `vendor/tycho/tyrell/docs/modules/bree.md`). The game walks one villager up to another (villager.js's `updateApproach`), and Bree strikes something up (`bree.strike`: a natter, a squabble, sweet nothings, a natter with a little one, a newcomer asking their way, or making it up, by converse.js's odds), runs it turn by turn on the minds' clock (who raises which topic, how each answer lands by degrees, a curt word sending someone off or turning it into a squabble), and ends it with an outcome for each; table talk is a group kind the game starts where two or more sit eating (`Natter.tables`). The game hears each turn (`bree:turn`) and says it: converse.js's pools are Cityspeak lines (`natterLines`), filled in by `fillTalk`, and news and messages are still gossip.js's and talk.js's. What each outcome does is declared in the kinds' `on`, in the game's own terms (`bond()`, moodlets, memories, the chronicle), and run once the minds' clock has moved (`Natter.flush`). The game owns space: Bree's `together` (both still in their chat tasks, or at the table) and `witnesses` (the room indoors, shouting distance outdoors), and a natter task put down ends its exchange. Bree's settings are `MIND_BREE` (in `MIND_MODULES`); gatherings stay the game's; and without Tyrell all of it is converse.js's (and villager.js's old exchange, for little ones and newcomers).

**The body and harm.** With the minds on Tyrell, villager.js's body chemistry is Athelas courses (`js/body.js`, `Body`; `vendor/tycho/tyrell/docs/modules/athelas.md`): ale, a cold, the flu, a bad toadstool and a sprain, each at villager.js's own pace (ale and a toadstool are levels falling through bands, a phase each, entered at the band the level says with a phase's `if`; a cold and the flu the germs' rise and fall, hastened by sleep). `v.chem` and `v.illness` are views of the courses (each level worked out from where its course has got to; a write such as a toadstool nibbled or a toast at a feast becomes an affliction), and what being poorly or in drink does to needs and choices is the phases' `rates`, `weigh` and `blocks` (so `mindRates` and `score()` leave it out); catching things and drinking stay the game's (contagion by who's near whom; the pint in hand is `task.data.ale` until it's down, `Body.drink`). Harm is Tyrell's Morgul (`vendor/tycho/tyrell/docs/modules/morgul.md`; settings `MIND_MORGUL`, lethality 0): a squabble that comes to blows (rarely: the squabble kind's `escalation`, `Scuffle.escalation`) is the `scuffle` kind, a fight by numbers, its wounds Athelas courses (`bruise`, `bloody_nose`), played on screen from the bridge's `scuffles` beats (`js/scuffle.js`, `Scuffle`: the `tussle` pose, `Scuffle.look`); pranks (`js/mischief.js`, `Mischief`: the `prank` action, tagged `harm`) are Morgul's traps (tripwire, snare: means declared through the bridge's `means`, each at a place of its own, `mf_spot_<x>_<y>`, all of them the game's to spring through the bridge's `traps`, drawn by `Mischief.draw`) and taints (a bad mushroom in someone's pot, their own Tyrell place, eaten at their next meal: meals are tagged `meal`), with Morgul's suspicion. What harm sets off is told to the game after the minds' clock moves (`Body.later`, `harmLater` for words a moment after); its words, the chronicle (so gossip carries it), memories and the game's feelings are the game's. How often is `SCUFFLE` and `MISCHIEF`'s (about one squabble in eleven comes to blows; a spoiled supper is about one prank in sixteen); `test/harm/` has the scripts that measured the body and harm against main (`wild.js` watches what squabbles and pranks come to in a village left alone, `speed.js` a day's CPU for two checkouts), and `test/minds.md` the numbers.

**Conversation (the wizard).** `js/threads.js` is the engine, and with the minds on Tyrell a talk runs on Tyrell's Voice (every thread a Voice thread and every line rule a Cityspeak line; Voice runs the subjects, beats, answers and how each lands, and the game keeps trust and respect, the talk's flags, the day's luck, the menus, the wizard's own lines, jokes, secrets and promises); the words live in talk packs, `talk/<name>.js`, plain data files that call `talkPack(name, () => { lines(...); addThread({...}); })`. They are listed in `TALK_MANIFEST` (threads.js; `test/check.sh` checks the list matches the folder) and loaded by `<script>` tag (so `file://` still works) only in a village played as the wizard: the core at once, the rest one at a time when idle. `talk/core.js`'s banner explains how to write one. Lines are chosen most-specific-first from rules over a flat facts dictionary (`factsOf`); placeholders must be facts it provides. `npm test` lints every pack and fuzzes talks.

## Rendering and art

- **Two canvas pixels per world pixel.** `RS`/`GS` = 2 in `util.js`. The art style is chunky top-down pixel art: each world pixel is a square block.
  - Most sprites are drawn at world size, then doubled pixel for pixel by `hd()`/`blit()` (`sprites.js`).
  - Villagers alone are drawn natively at double resolution on a half-pixel grid (`folkCanvas`), and carry `.hd`.
- **Outlines.** `outlineCanvas()` (`util.js`) rings a sprite in a darkened shade of its own colors. The color argument is ignored. It's Tycho's `sprite.outline` (`{ own: 0.42, grow: 'edge' }`) and a GPU copy; `makeCanvas`, `spriteFrom`, `disc`, `ellipseFill`, `scale2x` (under `hd()`) and `mirrorCanvas` are Tycho's sprite helpers too, by their options (`vendor/tycho/docs/sprite.md`).
- **Ground.** The ground lives in `Ground` (`world.js`): chunks of 32×32 tiles, each its own canvas, made when first seen (a flat sketch at once, the real painting nearest the camera first, a few milliseconds a frame in `stepPaint`) and let go when out of sight longest (`CHUNK_MAX`). `paintGroundGen` paints a rectangle one color per world pixel, then the hobbit-hole hills (`paintMound`), bridges and flower patches, and a final pass makes everything chunky and dithers it with a 4×4 Bayer pattern (`BAYER4`, `DITHER_STEP`). Everything it draws is placed by absolute coordinates, so chunks join without seams: keep it that way (no decisions that depend on the rectangle's edges).
  - After changing tiles, call `repaintRect` or `refreshGround`. To draw onto the ground, use `Ground.draw`.
  - `MAP_W`/`MAP_H` are variables; `setMapSize` (before building a world) remakes every map-sized array.
- **Scenery.** Statics (trees, bushes, buildings, props) carry a `gen` recipe and are re-made per season through `seasonalImage` (cached).
  - Long grass, tall grass, weeds and reeds are entries in `World.grass`, drawn by `drawTuft` (`nature.js`). Their `v` field selects the kind:
    - 0–7: grass and reeds
    - from `WILD_V` (100): the wild plants
    - from `TALL_V` (300): the tall grass
- **Visitors.** Figures from beyond the village who aren't villagers (the wizard) go in `Visitors` (`util.js`): `render()` y-sorts and draws them, collects their lights, and gives them speech bubbles like the folk.
- **Draw order.** Everything standing is y-sorted in `render()`, so tall grass in front of a villager covers them. Statics and grass come from `Scene` buckets (8×8 tiles) under the camera, not a scan of the whole map; the buckets rebuild when a list's length changes and once a second.
- **The GPU.** Where there's WebGL2 the world is drawn on the GPU by Tycho's renderer (`vendor/tycho/docs/renderer.md`): `viewGpu` (`main.js`) is the batcher and `vctx` its stand-in for the view's 2D context, so the drawing code is written as for a 2D canvas and must keep to what the stand-in takes (fillRect, drawImage, alpha, the blend modes, save/restore, setTransform/translate/scale/rotate, a rect clip, linear and radial gradients). Every picture drawn goes up to the GPU once, so a canvas that's painted again after it's been drawn needs `gpuDirty(canvas)` (the ground's chunks when a patch is repainted or drawn on), and one painted afresh every frame is marked `gpuLive` (the night's darkness). Without WebGL2, or with `?nogl` in the address, `vctx` is the view's own 2D context. `test/gpu.js` draws the same frame both ways and holds them to a few tones; the golden pictures are the 2D path's; the smoke run plays on the GPU. Text (the speech bubbles, names) stays on the overlay's 2D canvas, over it.
- **Light.** Night light is stepped pools (`Light.render`, `fx.js`), and the house interiors (`interior.js`) do the same. Avoid smooth gradients in world art.
- **Trees and bushes.** These are built procedurally per seed (`makeTree`, `makeBush`) and placed by habitat (`nature.js`: `plantWoods`, `plantNature`, `plantWildflowers`, `plantHill`) using soil, moisture, shade and settlement data from `terrain.js`.

## Conventions

- American English everywhere: comments, docs, in-game text and the talk packs, identifiers, function and variable names, object keys, fact names and thread ids, CSS classes and save keys (color, behavior, gray, center, neighbor, favorite, organize, meter; Mom, cookies, the mail). The Shire's voice stays (lad and lass, daft, aye, Gran, pudding, elevenses, autumn), and so do names (Gandalf the Grey, the Grey Havens). Comments and in-game text are plain prose; match the surrounding density and voice. `npm test`'s talk lint fails a line spelled the British way, and a save from before the change has its old names put right on load (`RENAMED` in `save.js`): a saved name that changes spelling goes in that table.
- Commits go straight to `main`. Subjects are short sentence-case statements of the player-visible change (for example "Hobbit-hole hills grow wild on top"). The pre-commit hook amends `js/version.js` itself.
